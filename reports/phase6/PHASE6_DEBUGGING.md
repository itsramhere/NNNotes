# Phase 6 debugging - 12 October 2026

Status: Phase 6 functional checks are verified on the emulator. Full phase sign-off remains pending because the combined regression run exposes an earlier handwriting render-handoff failure. Physical-device and Android 8 checks remain pending. No Phase 8 work was started.

## Scope and repairs

Debugging covered PDF import, navigation, editable annotation, selected-page export, flattened export and canvas pagination, using the plan's shared decisions and Phase 6 debugging requirements. Existing notebooks, the supplied APKM and inspection artifacts were preserved. Installation used `adb install -r`; application data was never cleared.

- Fixed the export-progress smart-cast compilation failure. Updated earlier tests for the required PDF repository and schema-5 migration. Earlier process fixtures explicitly use standard/infinite types instead of accidentally creating invalid PDF notebooks.
- Removed PDF from blank-notebook creation and reject that path in the repository. A PDF notebook now requires validated import.
- Import checks cancellation between copy reads and page validation. Errors distinguish password protection and invalid/unreadable/storage failures. Uncommitted files are cleaned up. Cancellation after Room commit retains the committed local PDF; a controlled DAO-boundary test covers that race.
- Replaced whole-document `PdfDocument` accumulation with a streaming PDF writer. Each page's JPEG is written immediately; only object offsets and the content snapshot remain between pages. Bitmap allocation is guarded by the device's actual memory budget.
- Corrected physical page dimensions: PDF MediaBox uses document points, while the flattened raster uses 150 DPI. Standard notes/canvas tiles use 595 x 842 points; imported pages use Android PdfRenderer's reported source dimensions.
- Snapshot page state and editable objects transactionally before rendering. Changes to the live notebook after the snapshot cannot alter later exported pages.
- Use AndroidX Ink's renderer for pressure pen/highlighter appearance, including the document-to-raster canvas transform. Independent visual inspection caught and verified correction of a displaced-ink defect.
- Missing image assets, invalid annotations and unavailable PDF sources fail export instead of silently producing incomplete backgrounds/content. Cancellation is checked during rendering and destination copying. Temporary output is removed and created destinations use the proper DocumentsContract deletion protocol.
- Canvas tiles clip to the chosen region, including partial final tiles, and retain left-to-right/top-to-bottom order. Added a visual A4 boundary/content preview, content-based initial bounds and safe pagination validation.
- PDF thumbnails now show source backgrounds. Visible-page rendering has bounded raster/cache budgets, zoom-aware resolution, cancellable stale jobs, error handling and detach/reattach lifecycle management. Standard/infinite notebooks do not create an unused PDF view.
- Disable export while ink, unsaved edits or page operations are pending. Added native pen/highlighter editing and picker-cancellation checks.
- Guard late ink callbacks against detached views. The older toolbar test explicitly waits for Compose changes to reach AndroidView. These changes do **not** establish that the remaining native regression is fixed.

## Remaining defects and limits

- **Open regression:** `Phase2UiTest.realEditorToolbarWriteEraseUndoRedoRecreateAndReopen` repeatedly times out at `saved(2)` after Highlighter -> Pen. It passes in an isolated invocation (`toolbar-sync-suite.txt`), but still fails after earlier lifecycle checks (`suite.txt`, `isolated-handwriting-ui.txt`, `lifecycle-guard-suite.txt`). The trace records the second stroke's completion without the normal finished-render handoff. A separate run crashed in native `libhwui.so` RenderThread with the same stack signature recorded during Phase 2. Exact root cause remains unproven. The app retains the completed record independently of that callback, but pending rendering can keep navigation/export blocked. This is not a clean combined-regression acceptance.
- Compared SwiftShader/OpenGL, SwiftShader/Vulkan, guest reboot and a complete host-GPU emulator restart without wiping data. Host graphics alone did not resolve the repeated timeout. No restricted Ink fallback, pinned-library upgrade or physical-device acceptance claim was introduced. Late-callback guarding and test synchronization did not eliminate the grouped failure.
- Physical tablet/stylus/palm and sustained native-rendering stress checks remain pending: only the API 36 x86_64 emulator is connected. Only an API 36 system image is installed; minimum-supported Android 8/API 26 runtime acceptance is pending.
- Low-storage and allocation failures are controlled injections, not an actual filled physical device. Arbitrary document-provider permission revocation/refused deletion is not exhaustively verified. Export attempts deletion through DocumentsContract; a provider can still refuse cleanup. If import commit state cannot be read after a failure, its local source is retained to avoid deleting a potentially committed notebook.
- Imported dimensions follow PdfRenderer's integer-point page API; sub-point source MediaBox fidelity and unusual PDF rotation/crop/annotation forms were not exhaustively tested. Export uses JPEG at quality 95 and 150 DPI, so output is flattened and rasterized as required.
- Native crashes can leave a test-owned notebook fixture when instrumentation cannot execute teardown. The runner never clears or sweeps the application's database to hide a failure.
- PDF source reclamation after permanent notebook deletion is not yet implemented: database metadata cascades, but unreferenced source files can remain on disk, like the earlier retained image assets. This is a storage-reclamation limitation, separate from failed-import/export cleanup exercised here.
